# Typert build reference

The build copies the unmodified `lib/types/*.d.ts` declarations from the installed `@deepseek-ai/dsh-typert-protocol` development dependency into `src/`. The official Typert generator indexes these declarations through the Host project references while analyzing the external Jev plugin: it recognizes `Remote` and `TypertRemoteService` only when their declaring package is the workspace-registered `@deepseek-ai/dsh-typert-protocol`, which this private mirror provides. This directory is excluded from pnpm workspaces and the plugin package; runtime imports continue to use the installed peer package.

The root `@deepseek-ai/dsh-typert-generator` development dependency is intentionally pinned to `0.2.1-alpha.2` and is not moved by `scripts/validation/bump-harness-version.mjs`. The 0.2.1-rc generator rejects this external workspace because installed peer packages merge-declare `TypertResourceMap`/`RemoteErrorDetailsMap` outside the analyzed face (“merged interface … contains a declaration outside this face”); the alpha.2 generator analyzes the current protocol declarations and emits the same Host/Remote artifacts. Revisit this pin only when a generator release supports external merged declarations, and verify byte-identical artifacts plus the compatibility smoke before changing it.
